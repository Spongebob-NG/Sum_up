#### CPU是如何执行程序的

先来讲一下最开始的**图灵机**. 图灵机的组成很简单 一条纸带 相当于内存 一个读写头 里面有控制单元和运算单元以及存储单元(存储单元称为图灵机的状态) 控制单元的功能就是来识别当前读写头位置的那个字符是数据还是指令 并且控制程序的流程. 运算单元的功能就是执行运算指令 存储单元就是用来存放数据. 如果说要计算1+2=3这个算式的话 读写头先把1 2 + 这三个字符写到纸带上 然后读写头把位置再移到1上面去 控制单元发现这是个数字 就把数字放到存储单元里面去. 然后读写头再继续把2读到存储单元里面去 之后读到+这个字符时 控制单元发现这是个符号 就让运算单元算出存储单元里面存放的两个数字的和 然后读写头再往右边移 把算出来的结果写到纸带上的格子中. 到了现在我们的计算机遵循的就是**冯诺依曼模型** 这个模型就是在图灵机的设计基础上 把设备都换成**电子元件** 并且用**二进制**来进行计算和存储 并且定义了计算机的基本结构分为五部分 运算器 控制器 存储器 输入设备和输出设备. 其中运算器和控制器都是在中央处理器 也就是CPU里面的

现在开始一个个说具体的硬件 首先就是**中央处理器(CPU)** 分为两种 一种是32位 一种是64位 具体就是依据CPU一次能计算多少位的数据来划分的. 这里的32和64说的是位宽 然后CPU内部又有一些组件 分别是控制器(用来控制CPU的工作) 逻辑运算单元(负责计算) 以及寄存器 寄存器又分通用寄存器 程序计数器和指令寄存器. 通用寄存器是用来计算的 比如说加减法 程序计数器里面存的是下一条要执行的指令的**地址** (是地址而不是指令本身!此时的指令还在内存里面) 指令寄存器里面存放的是当前正在执行的**指令本身** . 接下来介绍**总线** 作用就是让CPU能和内存以及其他设备进行通信 分为三种 地址总线 数据总线和控制总线 其中地址总线存的就是CPU将要操作的内存地址 数据总线就是读写内存里面的数据 控制总线用来发送和接收信号 比如说中断之类的.如果说要拿内存中的某个数据时 流程就是这样的: 先通过地址总线来确定在内存中的地址 然后控制总线就来控制是读命令还是写命令 最后就通过数据总线来传输数据. 然后再来说一下**线路位宽与CPU位宽之间的联系** **CPU位宽一般不能小于线路位宽(这里说的是地址总线 现在的CPU数据总线远远大于CPU位宽)** 不然就会效率很低 很痛苦. 如果说CPU位宽是32 地址总线和数据总线都是40位宽的话 那么CPU要处理至少两次才能拿到地址总线和数据总线里面的东西 并且如果说数据总线是64位宽的话 32位宽的CPU不能一次性算出两个64位数据相加的和 还要分成低位和高位 低位还要再处理一下进位 就很麻烦.所以说**CPU位宽通常都是要大于等于总线位宽的(不过这是之前的事情了 那些经典微处理器确实是这样的 但是在现在的高性能CPU中 外部数据总线的宽度会远远大于CPU位宽 因为为了吞吐量 会直接一次性刷入一个缓存行 而不只是那64或者32个字节)**. 然后如果是64位CPU的话 地址总线一般就是40位左右 够用就好 不然的话会考虑到晶体管或者主板的成本 以及功耗之类的问题 线路也会变得更复杂 反而会降低内存读取的速度.但是如果说32位的CPU装8G内存条的话 属实也没用 因为32位CPU一般对应的地址总线也是32位 根本就喊不出8G的空间.(不过其实有个**物理地址扩展**的技术 能通过多级页表切换来分配这些物理内存 比如说进程A占用前4GB内存 进程B占用后4GB内存 不过同时增加了开销) 而且**地址总线一般也不能比CPU总线位宽大** 因为32位CPU内部的寄存器等各类元件 位宽都是32位 有些环节地址是要存到寄存器里面的 **寄存器也存不下那么大的地址 只能扔掉**. 然后这里顺便再最后科普一下**指针大小和CPU位宽的关系** :(这个地方一开始是自己总结的 但是后面AI再帮我润色了一下)

```
其实不用想得太复杂，指针的大小，本质上就是地址的大小（因为指针里面存的就是内存地址）。

CPU 要操作数据，自然得先拿到地址。如果地址的位数和CPU的位数刚好一样，它们配合起来就会非常“融洽”。特别是现代的 64 位 CPU，如果指针大小也是 64 位（也就是 8 字节），CPU 只需要一条指令就能完美吞吐一个地址，操作起来极其方便。

当然，它们在架构上并不是严格非得一样。CPU 位宽和指针大小也可以不同，但那样硬件和编译器操作起来会非常麻烦和复杂。所以，现在行业内普遍达成了默契，统一采用 64位CPU + 64位指针 的黄金组合。
```

 最后再说一下**控制总线**一般是多少位 其实这个不是固定的 因为控制总线上的每一根线都是一个独立的开关 不是跟数据总线或者地址总线一样一起组成一个大数字 所以控制总线的线数取决于CPU架构师设计了多少种硬件交互机制 比如说读写控制信号 时钟与同步信号 中断信号等.

然后现在就来具体说一下程序执行的过程. 先是CPU读取程序计数器里面的值 这个值是指令的内存地址 然后控制单元通过地址总线指定好要访问的地址 控制单元再通过数据总线把这个地址里面存的数据拿出来给CPU 然后放到指令寄存器里面 之后程序寄存器里面的值就自增 **自增的单位就是根据指令的大小来的** **而不是CPU的位宽**  如果说是定长指令集的话 虽然是64位CPU 但是为了节省内存和提高译码效率 机器指令还是被设计成32位 所以每次PC加4  如果是**变长指令集**的话 PC增加多少完全**由控制单元的译码器来决定**  译码器看懂指令有多大 就往后加几  然后CPU里面的控制单元就来译码 如果说是计算的指令的话 就交给逻辑运算单元 如果是存储的指令的话 直接就由控制单元自己来完成了 所以说控制单元不仅控制了各种总线 还控制了具体的译码之类的环节 可谓是CPU的决策者 所以指令执行的周期就是 **取得指令->译码->执行指令->数据回写** 然后大部分事情都是由控制单元来控制决策的 

**然后现在说一下存储器的层次结构** 访问效率越来越慢 空间越来越大的顺序是 寄存器->L1缓存->L2缓存->L3缓存->内存->SSD硬盘->HDD硬盘  其中CPU cache(也就是那三个缓存)用的是SRAM芯片 是静态存储器 有电数据就能保持存在 一断电的话数据就丢失了.并且只有L1分数据缓存和指令缓存 是分开的 L2和L3没有分开. 内存是DRAM 也就是动态随机存取 DRAM和SRAM的区别就是 前者1个bit 只需要1个晶体管和1个电容就能存储 但是数据是存储在电容里面的 会不断漏电 所以就要一直刷新保证数据不丢失 所以叫动态. 后者1个bit需要4到6个晶体管 体积较大 所以存储密度不高 但是极快 之所以叫静态是因为有电就能保持数据不丢 不像DRAM那样要一直刷新.  然后**每个存储器只跟相邻一层的存储器打交道 一般不会跳跃打交道 除非是DMA直接内存访问(网卡 SSD能直接跟内存交换数据 不需要CPU和Cache插手) 以及一些非暂存指令(比如上传很大内存的图片 直接越过Cache line来写数据)**

**如何写出让CPU跑得更快的代码?** 其实就是利用了CPU的Cache.Cache由很多个Cache line组成 Cache line是CPU从内存读取数据的基本单位 每个Cache line载入的数据大小是64字节 但是还有其他额外的字节需要标志Cache line的身份和状态 所以每行Cache line在硬件方面占用的字节是要大于64字节.然后Cache line和内存地址是怎么映射的呢 这里简单讲一下直接映射 就是内存地址是由组标记+索引+偏移量来构成的  然后Cache line是由索引+有效位+组标记+数据块组成的 对于**直接映射** 就是通过取模的方式来让每个内存块(内存块是Cache line从内存里面访问的数据大小 一般是64字节)映射到唯一的一行Cache line 因为内存块数量远远大于Cache line数量 所以肯定会有很多的内存块映射到的是同一行Cache line 所以就会有索引和组标记这个东西 索引是为了能够快速找到对应的Cache line地址 组标记就是判断Cache line里面的数据是不是要访问的内存数据 然后偏移量就能从Cache line里面读取对应的字.(CPU读的不是整个数据块  而是所需要的一个数据片段 成为字 比如说32位CPU就是读4个字节) .  那**怎么提升数据缓存的命中率**呢 关键就是遍历数组的时候 一定要按顺序遍历 不要跳着遍历 不然很容易在对应的64字节里面找不到 还得在内存里面拉到Cache line里面 **如何提升指令缓存的命中率**呢 这里先说一下CPU的分支预测 有一个专门的硬件来干这样的事情 在还没来得及算的时候就会把指令提前写到指令缓存里面  如果预测中了的话就能直接执行指令缓存里面的指令  所以如果有一个里面都是随机值的数组 然后按照if(num<50) ... else ... 这样的格式执行操作 可以先排好序再进行操作 这样能提高**流水线**的效率(指令早就已经放到指令缓存里面了 这里提升的是流水线的效率 避免流水线后面的预测失败导致流水线停滞). 那**如何提升多核CPU的命中率**呢  现在一个线程可以在多核CPU上按照时间片来运行 这样的话每个CPU的L1和L2缓存命中率都不会很高 所以说最好是把一个线程放到一个单独的CPU上面来加快速度 就能提升多核的命中率

#### CPU缓存一致性

先来说一下CPU的缓存是怎么写入到内存里面的 分两种方案 第一种就是**写直达** 这种方案就是无论缓存有没有命中 都会写入到内存(命中的话就连着Cache line一起更新了 没命中的话就直接写回内存) 这样的话会花费大量时间 . 第二种是**写回**   大体来说就是 先改这个Cache块 先不写回内存 等到这个块**要被替换的时候才写入到内存(也就是说 当缓存不命中 并且对应的Cache块为脏的时候 再写回到内存)**  也就是说 如果要进行写操作 **写完之后就直接把这个块标记为脏的** 如果缓存命中了 就一直读缓存就好了

然而现在的CPU都是多核的 并且每个核心的L1和L2缓存都是各自独有的 所以就会出现**缓存一致性**的问题 比如说 如果用写回 那么当核心A写了一个数据 并且这个数据是核心A的L1/L2缓存里面的话 就暂时不会先写入到内存 然后核心B发现没这个数据 就会从内存里面取这个数据 但是由于A已经改了这个数据 所以就会出现核心A和核心B的**数据不一致**  解决这个问题也有两个方案 第一个是**写传播** 顾名思义就是 核心A写了某个数据的时候 要通知其他核心  第二个是**事务的串行化**  也就是说要保证其他核心看到**数据的变化是有顺序的** 比如核心C可能接收到的信息为 i=100 -> i=200 核心D可能接收到的信息为 i=200 -> i=100 虽然写传播了 但是顺序不一样 就会带来问题.

**解决写传播**问题的具体实现方式就是**总线嗅探** CPU需要每时每刻监听总线上的一切活动 如果核心A改了某个数据 那么就会把这个事件**通过总线**广播给其他核心 然后其他核心检查自己是不是有相同的数据 如果有的话就更新 不过如果没有的话 CPU也要把这个事件广播给该核心 会**加重总线负载**  并且总线嗅探**只能保证某个CPU更新数据这个事件能被其他CPU知道** 但是**并不能保证事务串行化**  那么接下来的**MESI协议**就既能保证事务串行化 又能减小总线带宽压力.M就是已修改的意思 E就是独占的意思 S是共享的意思 I是失效的意思(并且这些标记都是针对**一整个Cache line** 不是针对某一个数据). 如果说一个数据只被一个核心拥有 那么Cache line就是E 如果有多个核心拥有这个数据 那么Cache line就是S. 只有在Cache line状态是**E或者M的时候 代表这个Cache line暂时不用跟其他核心同步**  如果一个数据被多个核心共享 并且被某个核心更新了 那么该核心的Cache line就会变成M 并且其他核心变成I 失效.   总而言之 如果一个核心改了数据 如果是E或者M的话 就能接着改 不用跟其他核心同步 如果是S的话  就要把其他核心的Cache line标记为I 并且如果读这个数据 发现Cache line是I的话 真正最后改了这个数据的Cache line(标记为M)才会把数据写回内存 然后其他Cache line从内存里面拿(这里只讲没优化之前的) 

现在来科普一下为啥都有MESI这种协议了 还需要 **atomic**和**内存屏障**呢?  因为 假如核心A的Cache line是S 它想写数据的话 必须要等其他的核心Cache line变成I 才能继续执行下面的任务 但是这个过程实在是太慢了 所以硬件工程师为了**榨干CPU的效率(因为硬件工程师默认的方式是单线程 如果是多线程的话就交给软件工程师来做了)** 在写端会有一个**写缓冲区** 先是把要写的数据往缓冲区里面一扔 等其他核心都变成I之后 才把写缓冲区里面的数据更新到A的Cache line里面  并且接收端也有个**无效队列** 收到"变为I"的信号后会先放到无效队列里面 然后给A回复收到了 之后再慢慢处理队列里面的失效动作. 所以会发生以下的问题:

```c++
// 两个全局变量
int x = 0;
int y = 0;

// 线程 1 (运行在 Core 0)
void thread1() {
    x = 1; // 语句 A
    y = 1; // 语句 B
}

// 线程 2 (运行在 Core 1)
void thread2() {
    while (y == 0); // 语句 C：死等 y 变成 1
    assert(x == 1);  // 语句 D：断言 x 一定是 1 吗？
}
```

假设一开始x是S状态 y是E状态 core0会先把x=1放到缓冲区里面 然后直接处理y=1 并且更新完缓存 这个时候线程2的core1发现y是1 就直接跳过while循环了 并且直接执行下面的assert语句 此时x依然还是0 当然会断言失败

这个时候atomic就发挥作用了 会设定一个**写屏障**(强制把缓冲区里面的所有数据刷新到Cache line里面才执行后面的)以及**读屏障**(强制把失效队列里面的失效都处理完才执行后面的)

#### 伪共享

前面说了一些MESI协议用来解决顺序和带宽问题 现在再来说一下**伪共享**的问题. 如果说线程A修改的是变量a 线程B修改的是变量b 虽然A和B修改的变量看上去不一样 但是他们可能在同一个Cache line里面 所以会一直相互失效 相互同步 这样的话Cache line就会一直反反复复失效 从而**Cache line就失去了它的作用** 转而从内存里面抓取数据.为啥要叫做伪共享呢? 因为**他们的Cache line是一样的 看上去在共享同一个变量 其实他们是不同的变量** 所以就是假的共享 ->伪共享

那要如何解决伪共享呢 从**实际存储层面**上解决  可以使用**宏定义让Cache line对齐** 这样的话a和b变量就不会在同一个Cache line里面了. 从**应用层**解决 可以使用**字节填充**的方式 让**一个缓存行里面只有这一个变量** 其他字节都用字节填充的方式

#### CPU如何调度

**linux里面没有进程和线程的区分** 结构体都是一模一样的 唯一能区分的就是这两个task_struct共享的资源是否一样 如果一样的话就代表这两个线程共享同一个进程资源 但其实linux里面没有所谓的进程 这个进程只是作为用户的我们来讲 为了方便区分的 但是**在内核里面 其实进程和线程没啥区别** **它们都只是个task任务** 有自己的寄存器 pid 栈 ...  所以 linux内核里面的**调度器 调度的对象就是task_struct** 也就是任务 

补充:**进程和线程的底层区别** linux中 创建进程fork()和创建线程pthread_create()的**底层调用都是clone()** 区别只是在于**传入的参数不一样** 创建线程时会传入共享内存地址空间 共享文件系统信息 共享打开的文件描述符 等等标志 而创建进程的时候不会传入这些参数 从而实现资源隔离

linux中根据任务的**优先级**分为**实时任务**和**普通任务** **优先级数值越小代表优先级越高** 实时任务优先级在0~99范围内 普通任务优先级在100~139内  然后**实时任务调度**分为两个调度类 Deadline和Realtime 调度策略一共有三种 SCHED-DEADLINE 按照截止时间最近的优先调度 SCHED_FIFO 相同优先级的 按照先来先服务的原则 优先级高的能插队 SCHED_RR 相同优先级的任务 按照时间片轮流运行 刚用完时间片的任务会放到队尾 优先级高的也能抢占.  **普通任务调度**就是Fair调度类 调度器是CFS(complete fair scheduler完全公平调度器) 分为两种调度策略 SCHED_NORMAL是普通任务 SCHED_BATCH是后台任务(由于不和终端交互 所以可以降低优先级)

对于CFS算法调度 会有一个vruntime虚拟运行时间 vruntime=实际运行时间×NICE_O_LOAD÷weight (其中NICE_O_LOAD是nice为0的时的权重常数 这里看成一个常数就是了)**每次选一个vruntime最小的调度** 然后计算vruntime的时候会有一个**权重值在分母上** **权重值越高 vruntime结果值越低 越容易被调度** 并且权重值在内核里面有个转换表 是根据nice值来转换的 nice值越低代表权重越高 最后vruntime也就越低 与此同时nice值也能修正优先级priority(也就是之前说的0~99 以及100~139那个) priority对应的是整个调度系统的调度策略 比如说决定是实时还是普通 是Deadline还是Realtime(不过普通任务的priority是一定不会小于100的 初始值是从120开始的 nice的范围是-20~19). 最后说一下**CPU的运行队列** 每个CPU都有自己的运行队列 **每个运行队列又包含3个队列**: Deadline的 实时任务的 以及CFS运行队列 其中CFS是用红黑树来描述的 按照vruntime大小来排序的  按照优先级: Deadline>Realtime>Fair

#### 软中断

先来讲一下啥是**中断** 中断就是操作系统收到硬件的中断请求 会打断正在执行的程序 然后调用内核中的中断程序来响应请求. 而**中断处理程序在响应中断的时候 可能会临时关掉中断** 因为中断不能被打扰 要执行完这个中断之后才能接着执行下一个中断 所以中断处理程序必须要快速. 所以中断能分为两部分 第一个是**硬中断** 第二个是**软中断**.硬中断就是快速处理中断 先关闭中断请求 执行完一些耗时很短的工作 如果工作要花费的时间很长的话 再把任务交给软中断 负责处理没完成的事情 不过**交给软中断的时候 中断请求就要打开了 避免错过其他中断请求**. 然后linux能通过一些命令观察中断次数 中断次数变化率 并且如果top的时候发现CPU在**软中断上的使用率比较高**的话 就代表**系统开销被软中断占据**了 这个时候就能分析是哪种软中断 一般来说都是因为**网络接收软中断**导致的 如果是的话就用命令检查是**哪个网卡接收了大量网络包** 再抓包 分析源头是否为**非法地址** 如果是的话就设立**防火墙**
